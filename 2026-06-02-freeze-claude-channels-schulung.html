Claude Channels Research Preview

Externe Ereignisse live in deine laufende Claude-Session pushen — von Telegram, Discord, iMessage oder eigenen Webhooks. Ein Kanal ist die Brücke zwischen der Welt da draußen und Claude auf deinem Mac.

Kapitel 1 · Konzept

Was ist ein Claude Channel?

Ein Channel ist ein MCP-Server, der externe Ereignisse in deine laufende Claude Code Session überträgt — damit Claude auf Dinge reagieren kann, die passieren, während du nicht am Terminal bist.

Die Kernidee in einem Satz

Du schickst dir selbst eine Telegram-Nachricht vom iPhone — und Claude auf deinem Mac liest sie, bearbeitet die Aufgabe, und antwortet dir zurück im Chat. Keine neue Session, kein Cowork öffnen, keine Kontext-Übergabe. Claude ist in derselben Session, mit demselben Dateizugriff, mit dem vollen Cowork OS Kontext.

Channels vs. die Alternativen — wann was?
📡

Channel — wenn du Ereignisse rein pushst

"Schick dir eine Telegram-Nachricht und Claude reagiert in deiner laufenden Session auf deinem Mac, mit deinen echten Dateien." Bidirektional möglich. Event-driven, nicht polling-driven.

🖱️

Remote Control — wenn du Claude steuerst

"Du willst den nächsten Prompt selbst eintippen, aber von deinem iPhone aus." Kein externer Event — du gibst aktiv Input. Channel vs. Remote Control: Push vs. Pull.

Research Preview — was das bedeutet

Channels sind noch in der Research Preview. Anforderungen: Claude Code v2.1.80+, claude.ai Login (kein API Key), Bun installiert. Nur offizielle Anthropic-Plugins sind freigegeben (Telegram, Discord, iMessage, Fakechat). Eigene Channels funktionieren mit dem --dangerously-load-development-channels Flag.

Kapitel 2 · Architektur

Wie funktioniert ein Channel technisch?

Ein Channel ist ein MCP-Server, der auf deinem Mac läuft. Claude Code startet ihn als Subprocess und kommuniziert über stdio. Der Channel-Server ist die Brücke zwischen externen Systemen und deiner Session.

Architektur-Überblick
EXTERNE WELT                           DEIN MAC

📱 Telegram Bot API ──→ 🔌 Channel Server (MCP) ──stdio──→ 🤖 Claude Code Session

🔔 Webhook / CI ──→ 🔌 Channel Server (HTTP+MCP) ──────────→ 🤖 Claude Code Session

📲 iMessage DB ──→ 🔌 Channel Server (AppleScript) ────→ 🤖 Claude Code Session
🔌

Chat-Plattformen (Telegram, Discord)

Plugin läuft lokal und pollt die Platform-API. Wenn jemand dem Bot schreibt, leitet das Plugin die Nachricht an Claude weiter. Keine URL muss öffentlich sein — alles bleibt lokal.

🪝

Webhooks (CI, Monitoring)

Server lauscht auf lokalem HTTP-Port. Externe Systeme senden POST-Requests dorthin, der Server pusht den Payload zu Claude. Auch intern anwendbar: eigene Scripts, Cron-Jobs, Notion Automationen.

Was in der Session ankommt — das Channel-Tag
# So sieht Claude das Ereignis in seiner Session: <channel source="telegram" chat_id="123456"> Capture Session: [Wispr-Transkript rein pushen] </channel> # Oder ein CI-Webhook: <channel source="webhook" severity="high" run_id="1234"> build failed on main: https://ci.example.com/run/1234 </channel>
Wie Claude Code den Channel startet
# Claude Code mit einem Channel starten: claude --channels plugin:telegram@claude-plugins-official # Mit mehreren Channels gleichzeitig: claude --channels plugin:telegram@claude-plugins-official plugin:discord@claude-plugins-official # Eigenen/Dev-Channel (Development Mode): claude --dangerously-load-development-channels server:mein-webhook

Wichtig: Channel ist nur aktiv solange die Session läuft

Events kommen nur an, während die Session offen ist. Für ein Always-On-Setup: Claude in einem Hintergrundprozess oder persistenten Terminal-Tab laufen lassen. In Cowork Desktop App kannst du eine dauerhaft offene Session einrichten.

Wie Claude reagiert — der Response-Flow
📥

1. Event empfangen

Channel-Server pusht das Ereignis als <channel>-Tag in Claudes Kontext. Claude sieht es wie eine Nachricht.

⚡

2. Claude handelt

Claude liest, plant, führt aus — mit deinen echten Dateien, deinem Cowork OS, deiner Methoden-Bibliothek. Keine neue Session, kein Kontext-Verlust.

📤

3. Antwort zurückschicken

Bei bidirektionalem Channel ruft Claude das Reply-Tool auf. Antwort landet im selben Telegram/Discord-Chat. Im Terminal siehst du den Tool-Call, nicht den Response-Text.

Kapitel 3 · Verfügbare Kanäle

Unterstützte Kanäle

Vier Kanäle sind in der Research Preview verfügbar. Alle sind Plugins aus dem offiziellen Anthropic-Marketplace und brauchen Bun als Runtime.

✈️ Telegram 🎮 Discord 💬 iMessage 🧪 Fakechat (Demo)
✈️

Telegram

Telegram-Bot erstellen via BotFather, Plugin installieren, Token konfigurieren, Konto koppeln. Bidirektional: Claude antwortet direkt im Telegram-Chat. Kein API-Server nötig — Plugin pollt Telegram API lokal.

Bidirektional Kostenlos 5 Schritte Setup
🎮

Discord

Discord Developer Portal, Bot erstellen, Message Content Intent aktivieren, Bot einladen, Plugin installieren. Antwortet in DMs. Gut für Entwickler-Workflows.

Bidirektional Dev-nah 7 Schritte Setup
💬

iMessage

Kein Bot-Token, kein externer Service. Liest Messages-Datenbank direkt (~/Library/Messages/chat.db). Antwortet via AppleScript. Nur macOS. Full Disk Access nötig. Schreib dir selbst — Claude antwortet.

Nur macOS Kein Konto nötig Disk Access
🧪

Fakechat (Demo)

Localhost Chat-UI auf http://localhost:8787. Kein Account, keine Auth, kein Setup außer Plugin. Perfekt zum Testen des Channel-Konzepts bevor man echte Plattform verbindet.

Kapitel 4 · Quickstart

Erster Start: Fakechat & iMessage

Zwei Wege zum ersten Channel-Erlebnis. Fakechat zum Konzept verstehen (5 Minuten), iMessage für den echten ersten produktiven Einsatz.

Voraussetzung: Bun installieren
# Bun installieren (einmalig) curl -fsSL https://bun.sh/install | bash # Prüfen: bun --version
Weg A: Fakechat — Konzept verstehen (5 Min)
1

Plugin installieren

In Claude Code oder Cowork Terminal:

/plugin install fakechat@claude-plugins-official
2

Claude mit aktiviertem Channel starten

claude --channels plugin:fakechat@claude-plugins-official
3

Browser öffnen und Nachricht senden

Öffne http://localhost:8787 und tippe:

"Was liegt gerade in meinem Cowork OS 03_Sonstiges Ordner?"
4

Claude reagiert

Die Nachricht kommt als <channel source="fakechat"> in Claudes Session. Claude liest, arbeitet, antwortet im Browser-Chat.

Weg B: iMessage — Produktiv vom iPhone
1

Full Disk Access gewähren

System Settings → Privacy & Security → Full Disk Access → Terminal (oder deinen bevorzugten Terminal) hinzufügen. Ohne das scheitert der Channel sofort.

2

Plugin installieren

/plugin install imessage@claude-plugins-official
3

Claude mit iMessage Channel starten

claude --channels plugin:imessage@claude-plugins-official
4

Dir selbst schreiben

Öffne Messages auf deinem iPhone → schreib dir selbst (deine eigene Nummer oder Apple ID). Erste Antwort triggert macOS-Prompt: "Darf Terminal Messages steuern?" → OK klicken.

# Erste Testnachricht an dich selbst (vom iPhone): "Capture Session Prep: CHS Weekly heute mit Sarah Schnitzler"
Telegram Setup (für dauerhaften produktiven Einsatz)
1

Bot bei BotFather erstellen

In Telegram: @BotFather öffnen → /newbot senden → Name vergeben → Bot-Token kopieren.

2

Plugin installieren & konfigurieren

/plugin install telegram@claude-plugins-official /reload-plugins /telegram:configure DEIN_BOT_TOKEN
3

Mit Channel starten & koppeln

claude --channels plugin:telegram@claude-plugins-official # Telegram: Nachricht an deinen Bot senden → Pairing-Code erhalten /telegram:access pair DEIN_CODE /telegram:access policy allowlist # nur du kannst schreiben

Pro-Tipp: Cowork immer mit Channel starten

Wenn du Claude Code täglich nutzt, kannst du einen Alias anlegen der Claude immer mit deinem bevorzugten Channel startet:

# In ~/.zshrc oder ~/.bashrc: alias cc='claude --channels plugin:imessage@claude-plugins-official' # Dann einfach: cc
Kapitel 5 · Fortgeschritten

Bidirektional, Sicherheit & Permission Relay

Channels können mehr als Einweg-Push. Mit Reply-Tools antwortet Claude zurück in den Chat. Mit Permission Relay genehmigst du Claudes Aktionen vom iPhone aus.

Einweg vs. Bidirektional
→

Einweg-Channel (One-way)

Externe Ereignisse kommen rein, Claude handelt in der Session. Keine Antwort zurück in den externen Kanal. Ideal für: Webhook-Empfänger, CI-Alerts, Monitoring-Events, Notion-Trigger.

Einfacher Kein Reply-Tool nötig
⇆

Bidirektionaler Channel (Chat-Bridge)

Claude antwortet zurück über denselben Kanal. Du fragst von Telegram, Claude antwortet in Telegram. Telegram/Discord/iMessage sind alle bidirektional. Braucht ein Reply-Tool im Server.

Mächtiger Reply-Tool nötig
Sicherheit — Allowlists

Wichtig: Ungated Channel = Prompt Injection Risiko

Jeder, der eine Nachricht an deinen Channel senden kann, kann Text in Claudes Kontext schreiben. Deshalb: Sender-Allowlist immer konfigurieren. Die offiziellen Plugins (Telegram, Discord) koppeln über einen Pairing-Code und sperren dann auf Allowlist. iMessage erlaubt automatisch deine eigene Apple ID; andere Kontakte musst du explizit erlauben.

🔐

Telegram/Discord

Pairing-Code bei erster Nachricht → Code in Claude bestätigen → Sender-ID auf Allowlist. Dann: /telegram:access policy allowlist

🍎

iMessage

Du selbst → automatisch erlaubt. Andere Kontakte: /imessage:access allow +49XXXXXXX. Handles sind Telefonnummern oder Apple ID-Mails.

🪝

Eigener Webhook

Allowlist im Code: const allowed = new Set(['dev', 'mein-token']) — Sender aus Header prüfen bevor Event an Claude gepusht wird.

Permission Relay — Claudes Aktionen vom iPhone genehmigen

Das mächtigste Feature

Wenn Claude eine Aktion ausführen will, die Genehmigung braucht (Datei schreiben, Shell-Befehl), erscheint normalerweise ein Dialog im Terminal und die Session wartet. Mit Permission Relay kommt derselbe Prompt auch in deinen Chat-Kanal. Du antwortest mit yes abcde oder no abcde und Claude macht weiter — ohne dass du am Mac sitzen musst.

Permission Relay — Ablauf
1

Claude will Aktion ausführen (z.B. Datei schreiben)

Lokaler Terminal-Dialog öffnet sich. Session pausiert.

2

Channel-Server empfängt Permission Request

Mit request_id (5 Kleinbuchstaben), Tool-Name, Beschreibung und Input-Vorschau.

3

Prompt erscheint in deinem Chat

# Was in Telegram/iMessage ankommt: Claude wants to run Write: Schreibt in Coach HQ/CHS/_mandat-akte.md Reply "yes abcde" or "no abcde"
4

Du antwortest vom iPhone

yes abcde

Lokaler Dialog schließt sich, Claude führt die Aktion aus. Wer zuerst antwortet (Terminal oder Handy), gewinnt.

Permission Relay nur mit vertrauenswürdigen Sendern

Wer über den Channel antworten kann, kann Tool-Nutzung in deiner Session genehmigen. Deshalb Allowlist immer eng halten — nur du selbst oder wenige explizit vertraute Personen.

Kapitel 6 · Deine Praxis

Deine Use Cases im Cowork OS

Sechs konkrete Szenarien, wie Channels dein Cowork OS erweitern — speziell zugeschnitten auf Coaching-Praxis, Mandat-Arbeit und Selbstständigkeits-Aufbau.

1

Capture Session Prep vom iPhone — unterwegs vor dem Coaching-Termin

Du bist im Zug auf dem Weg zu einem Klienten. Schreib dir selbst via iMessage einen kurzen Kontext-Dump. Claude in deiner laufenden Session auf dem Mac liest es, greift auf die Mandat-Akte zu und sendet dir eine kompakte Vorbereitungs-Notiz zurück.

Beispiel-Nachricht an dich selbst (iMessage/Telegram)
"Capture Session Prep: CHS IT-Führungsrunde heute 14:00. Letzte Session war Dual Excellence-Diagnose. Bereite mir 3 Fragen und Methodenempfehlung vor."
Was Claude zurückschickt

Lädt Mandat-Akte, liest letzte Gesprächs-Spur, sendet kompakte Session-Vorbereitung zurück in deinen Chat.

2

Capture Reasoning direkt nach der Session — Diktat via Telegram

Statt Wispr-Transkript manuell in Cowork zu übergeben: Du gehst aus der Session, sprichst 90 Sekunden in Telegram, Claude empfängt das Diktat und schreibt es direkt in die Reasoning-Spur der Mandat-Akte.

Ablauf
# In Telegram an deinen Bot: "Capture Reasoning: CHS IT heute. Sarah hatte wieder den Reflex, jedes Problem sofort zu lösen bevor sie es vollständig gehört hat. Ich hab es dieses Mal gespiegelt ohne zu konfrontieren. Sie hat... [90 Sekunden Diktat]" # Claude schreibt direkt in die Reasoning-Spur von _mandat-akte.md # Claude sendet dir Bestätigung zurück in Telegram
3

Triage unterwegs — Inbox leeren vom iPhone

Du hast im Laufen 3 Sprach-Memos auf dem iPhone aufgenommen. Per iMessage pushst du die transkribierten Texte an Claude, der sie klassifiziert und routet — Capture-Befehl als Vorschlag oder direkt ausführen.

Nachricht
"Triage das: [Transkript 1: hatte ein Gespräch mit Decadia über neues IT-Mandat...] [Transkript 2: Idee für Venture Radar: Buchhaltungs-Automatisierung...] [Transkript 3: Erinnere mich: nächste Woche KIT Alumni-Treffen...]"

Claude klassifiziert: 1 = Capture Lead/Mandat, 2 = Capture Marktimpuls, 3 = Privates HQ Reminder. Schreibt entsprechend oder schlägt Befehle vor.

4

Eigenmarke HQ: CI/CD-Alert wenn Build fehlschlägt

Dein machs-fuer-mich-site Repo auf GitHub hat einen fehlgeschlagenen Build. Ein Webhook von GitHub Actions schickt den Fehler-Report direkt in deine Claude-Session. Claude analysiert, identifiziert die Ursache und schlägt Fix vor — ohne dass du aktiv GitHub checken muss.

Webhook-Payload der ankommt
<channel source="github-webhook" severity="high"> Build failed: machs-fuer-mich-site main branch Error: Cloudflare Worker: Cannot find module '@anthropic-ai/sdk' Run: https://github.com/jaymanuzon/machs-fuer-mich/actions/runs/1234 </channel>
5

Venture Radar: Externen Alert wenn ein Kandidat interessant wird

Der Venture Radar läuft als Schedule. Wenn ein besonders starker Kandidat (Equity-Score ≥ 4) identifiziert wird, pusht er einen Alert über einen Webhook an deine Session. Claude erweitert die Analyse und sendet dir eine Kurzfassung via Telegram.

Webhook aus dem Schedule-Script
# Am Ende des Venture-Radar-Scripts: curl -X POST localhost:8788 \ -d "High-Score Kandidat: KI-gestützte Steuerberatung für KMU Equity-Score: 4/5, Marktreife: 3/5, AI-Takeover: 5/5 Bitte erweiterte Analyse erstellen."
6

Permission Relay: Claude-Aktionen vom iPhone genehmigen

Du hast Claude eine komplexe Schreib-Aufgabe gegeben (neuen Skill bauen, Mandat-Akte aktualisieren) und bist dann weg vom Mac. Claude braucht Genehmigung zum Schreiben. Mit Permission Relay kommt der Prompt in deinen Chat — du antwortest mit yes/no und Claude macht weiter.

Was du auf dem iPhone siehst
# In Telegram/iMessage: Claude wants to run Write: Schreibt neue Session-Vorbereitung in Coach HQ/.../CHS/_mandat-akte.md Reply "yes xkzmn" or "no xkzmn" # Deine Antwort: yes xkzmn

Empfehlung: Zwei-Phasen-Einführung

Phase 1 (heute): iMessage-Channel einrichten — 4 Schritte, kein Bot-Setup, sofort nutzbar. Teste Use Case #1 (Session Prep) und #3 (Triage). Kein Permission Relay, kein Webhook. Nur: Nachricht rein, Claude reagiert.

Phase 2 (wenn Phase 1 sitzt): Telegram-Channel mit Permission Relay einrichten. Use Case #2 (Capture Reasoning) und #6 (Permission Relay vom iPhone) schalten eine neue Qualität frei: du kannst lange autonome Tasks starten und sie vom iPhone steuern.
