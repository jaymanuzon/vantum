Kapitel 1 · Überblick

Was ist Claude Code?

Claude Code ist ein agentisches Werkzeug — kein Chatbot, der auf Prompts wartet, sondern ein Assistent, der Dateien liest, Befehle ausführt, Änderungen vornimmt und Aufgaben eigenständig durcharbeitet. Entwickelt für Code, aber vielseitig für alles einsetzbar, das über die Kommandozeile läuft.

Der entscheidende Unterschied zu Cowork

Cowork (diese Desktop-App hier) ist eine Oberfläche mit visuellen Elementen, Konnektoren und Skills. Claude Code ist die tiefere Schicht darunter: ein Terminal-nativer Agent mit direktem Zugriff auf dein Dateisystem, deine Shell und Git. Cowork ist eine von mehreren Oberflächen, auf denen Claude Code läuft. Du nutzt Claude Code also bereits, nur über eine GUI statt dem Terminal.

Kapitel 2 · Mechanik

Der Agentic Loop

Jede Aufgabe durchläuft denselben Kreislauf: Kontext sammeln, handeln, verifizieren. Kein einmaliger Prompt-Response-Tausch, sondern ein iterativer Prozess mit Dutzenden Werkzeugnutzungen pro Aufgabe.

Schritt 1
🔎 Kontext sammeln
Dateien lesen, suchen, verstehen
→
Schritt 2
⚡ Handeln
Bearbeiten, ausführen, schreiben
→
Schritt 3
✅ Verifizieren
Tests, Ausgaben, Ergebnisse prüfen
↩

Du bist Teil des Loops

Du kannst jederzeit eingreifen, korrigieren und neu ausrichten. Esc stoppt sofort mit erhaltenem Kontext. Esc Esc oder /rewind öffnet das Rewind-Menü für einen Rollback. /clear setzt den Kontext zurück zwischen nicht zusammenhängenden Aufgaben.

Kapitel 3 · Kontinuität

Gedächtnis & Kontinuität

Jede Claude Code Session startet mit leerem Kontext. Zwei Mechanismen tragen Wissen über Sessions hinaus: CLAUDE.md (du schreibst es) und Auto Memory (Claude schreibt es selbst).

📋

CLAUDE.md — deine Anweisungen

Markdown-Datei mit persistenten Instruktionen. Claude liest sie bei jedem Session-Start. Ideal für: Build-Befehle, Konventionen, Architektur-Entscheidungen, Workflow-Regeln, "Always do X"-Regeln.

Du schreibst es Explizit Jede Session
🧠

Claude speichert selbst, was für zukünftige Sessions nützlich ist: Build-Befehle die funktioniert haben, Debugging-Erkenntnisse, Präferenzen die es bemerkt. Erste 200 Zeilen von MEMORY.md laden immer.

Faustregel für CLAUDE.md-Länge

Ziel: unter 200 Zeilen. Für jede Zeile fragen: "Würde das Weglassen dazu führen, dass Claude Fehler macht?" Wenn nein: streichen oder in einen Skill auslagern. Zu lange Dateien führen dazu, dass Claude wichtige Regeln ignoriert.

Auto Memory — Struktur
# ~/.claude/projects/<project>/memory/ MEMORY.md # Index, wird jede Session geladen (max 200 Zeilen) debugging.md # Details zu Debugging-Mustern (on demand) api-conventions.md # API Design-Entscheidungen (on demand) ... # Weitere Topic-Dateien die Claude selbst anlegt

Dein Cowork OS nutzt dasselbe Prinzip — bewusst

Deine CLAUDE.md-Dateien in jeder Workstation und deine MEMORY.md-Dateien sind exakt das Gedächtnis-System von Claude Code. Der Unterschied: Du befüllst MEMORY.md manuell (was präziser ist), Claude Code macht das automatisch. Die Auto-Memory in Cowork OS ergänzt das, wo du es lässt.

Kapitel 4 · Erweiterbarkeit

Skills, MCP, Hooks & Subagents

Claude Code lässt sich in vier Dimensionen erweitern. Jede adressiert einen anderen Bedarf — von wiederkehrenden Workflows über externe Dienste bis hin zu deterministischer Automatisierung.

🛠️

Skills — wiederholbare Workflows

Eine SKILL.md-Datei in .claude/skills/. Claude lädt sie bei Bedarf oder wenn der Name passt. Eigene Slash-Commands: /review-pr, /deploy, /prd-session. Inhalt lädt nur bei Nutzung, nicht bei Session-Start — kein Kontext-Overhead.

🔌

MCP — externe Dienste

Model Context Protocol verbindet Claude mit Notion, Gmail, Datenbanken, Figma, APIs. Einmal eingerichtet, liest und schreibt Claude direkt darin. Das sind deine aktiven Notion/Gmail-Konnektoren in Cowork.

⚡

Hooks — deterministische Trigger

Shell-Befehle VOR oder NACH Claude-Aktionen. Im Gegensatz zu CLAUDE.md-Anweisungen: nicht verhandelbar, immer ausgeführt. Beispiel: nach jedem Datei-Edit automatisch lint, oder Derived State Check.

🤖

Subagents — isolierte Kontext-Fenster

Claude delegiert Unteraufgaben an eigene Agent-Instanzen mit frischem Kontext. Kein Kontext-Overflow im Hauptgespräch. Ideal für Recherche, Review, oder spezialisierte Analyse.

Skill-Anatomie (direkt auf dein OS übertragbar)
# .claude/skills/session-prep/SKILL.md --- name: session-prep description: Bereite eine Coaching-Session vor basierend auf der Mandat-Akte disable-model-invocation: true # manueller Trigger, nicht automatisch --- Analysiere die Mandat-Akte für $ARGUMENTS und erstelle: 1. Session-Ziel basierend auf letztem Gesprächseintrag 2. Drei vorbereitete Coaching-Fragen (hypothetisch, systemisch, skalierend) 3. Methodenempfehlung aus der Bibliothek (Phase Fit + Mindset) 4. Kurze Klienten-Haltungs-Einschätzung basierend auf letztem Reasoning
Hook-Beispiel: Derived State nach Mandat-Akte-Edit
# .claude/settings.json { "hooks": { "PostToolUse": [{ "matcher": "Write|Edit", "hooks": [{ "type": "command", "command": "bash ~/Documents/Claude/Cowork\\ OS/00_Resources/2026-05-30-derived-state-check.sh" }] }] } }
Subagent-Anatomie
# .claude/agents/hostile-reviewer.md --- name: hostile-reviewer description: Prüft Inhalte als gegnerischer Reviewer tools: Read, Grep, Glob model: opus --- Du bist unabhängiger, skeptischer Reviewer ohne Kontext zur Entstehung. Prüfe jeden Claim auf Belastbarkeit. Keine Konstruktivität. Nur Schwächen enumerieren, mit Risiko-Gradient (hoch / mittel / niedrig).

Wann welche Extension?

CLAUDE.md → "Immer gelten, jede Session" · Skill → "Nur wenn ich es brauche, wiederkehrend" · Hook → "Muss passieren, ohne Ausnahme, deterministisch" · Subagent → "Braucht eigenen Kontext, komplex, isoliert" · MCP → "Externes System anbinden"

Kapitel 6 · Wachstum

Ungenutzte Potenziale

Acht konkrete Möglichkeiten, die du noch nicht oder noch nicht vollständig nutzt. Jede mit verbatim Befehl oder Prompt zum direkten Ausprobieren. Sortiert nach Aufwand-Wirkung-Verhältnis.

1

Hook: Derived State automatisch nach Mandat-Akte-Edit auslösen

Dein derived-state-check.sh läuft per wöchentlichem Schedule. Die Derived-State-Regel sagt aber: "Task erst fertig wenn Endpunkt nachgezogen und verifiziert." Ein PostToolUse-Hook stellt das unmittelbar nach jedem relevanten Edit sicher — nicht erst nächste Woche.

Aufwand: 15 Min · Wirkung: Hoch · Direkt anwendbar
# In .claude/settings.json ergänzen { "hooks": { "PostToolUse": [{ "matcher": "Write|Edit", "hooks": [{ "type": "command", "command": "bash ~/Documents/Claude/Cowork\\ OS/00_Resources/2026-05-30-derived-state-check.sh 2>/dev/null &" }] }] } }
2

Subagent für vollständige Engagement-Tiefenrecherche

Vor einem Briefing oder einer Session liest ein Subagent alle Engagement-Files (PPTX, PDFs, Mandat-Akte) und erstellt eine Lageeinschätzung, ohne deinen Hauptkontext zu füllen. Direkte Antwort auf die Feedback-Memory "Engagement-Material vollständig sichten vor Substrat-Bau".

Prompt zum Ausprobieren (in Cowork)
"Nutze einen Subagenten für folgende Aufgabe: Lies alle Files in Coach HQ/Coach HQ Resources/Engagements/RWE AG/CHS/ — inklusive alle PPTX und PDFs. Erstelle eine kompakte Lageeinschätzung: offene Themen, letzte Session, Muster über Personen. Max 1 Seite."
3

Writer/Reviewer Pattern für Coaching-Materialien

Parallele Sessions: Session A entwirft ein Deck oder eine Intervention, Session B reviewt es ohne Kenntnis des Erstellungskontexts. Unabhängiger als hostile-review in einer Session, weil der Erstellungskontext nicht im Kontext-Fenster sitzt.

Workflow (zwei separate Cowork-Sessions)
# Session A (Writer) "Entwirf eine 90-Min Workshop-Agenda für CHS Leadership zu Dual Excellence. Speichere unter Coach HQ/.../chs-workshop-agenda.md" # Session B (Reviewer) — neues Gespräch, kein History "Lies @Coach HQ/.../chs-workshop-agenda.md und review es als skeptischer Teilnehmer: Was fehlt? Was überzeugt nicht? Keine Reparatur — nur Schwächen benennen."
4

Remote Control: Von unterwegs in laufende Sessions eingreifen

Wenn eine lange Recherche oder ein Engagement-Aufbau läuft, kannst du per iPhone/Browser über Remote Control eingreifen. Nicht von vorn beginnen, sondern die laufende lokale Session weiter steuern, ohne am Mac zu sitzen. Besonders nützlich bei langen Triage- oder Capture-Tasks.

Einrichten (im Terminal oder Desktop App)
/remote # Öffnet Remote Control Link # Link an iPhone schicken → im Browser öffnen # Session live sehen und eingreifen
5

Eigenmarke HQ: GitHub Actions für Auto PR-Review

Für dein machs-fuer-mich-site Repo könntest du Claude Code GitHub Actions einrichten: jeder PR bekommt automatisch einen Code-Review, der auf Cloudflare Worker Korrektheit, KI-Ampel-Logik und Claude API-Nutzung prüft. Null Zusatzaufwand nach Setup.

Workflow-Datei (in .github/workflows/)
# .github/workflows/claude-review.yml on: [pull_request] jobs: review: runs-on: ubuntu-latest steps: - uses: anthropics/claude-code-action@beta with: prompt: "Review this PR for machs-fuer-mich. Focus: Cloudflare Worker correctness, Claude API call, KI-Ampel business logic, intake flow integrity." claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
6

Terminal CLI für Batch-Verarbeitung von Transkripten

Du verarbeitest Wispr-Transkripte manuell über Cowork. Mit non-interaktivem CLI könntest du einen Ordner mit Transkripten automatisch klassifizieren und den passenden Capture-Befehl ausgeben lassen — als Vorschlag zur Bestätigung.

Befehl (im Terminal)
# Installation Terminal CLI zuerst curl -fsSL https://claude.ai/install.sh | bash # Dann: Transkript klassifizieren cat ~/Documents/Wispr/2026-06-02-session.txt | claude -p \ "Bestimme den Capture-Typ: Session / Gespräch / Reasoning / Selbstcoaching. Gib den exakten Capture-Befehl aus, den ich in Cowork eingeben soll."
7

Cloud Routinen: Venture Radar unabhängig vom Mac

Dein Venture Radar läuft per Schedule auf deinem Mac. Mit Claude Code Cloud Routinen läuft der Task auf Anthropic-Infrastruktur — auch wenn dein Mac aus ist. Der Output kommt als Session zurück, die du asynchron reviewen kannst.

Einrichten (claude.ai/code → Schedules)
# Im Terminal CLI: Schedule anlegen /schedule # → Trigger: Montag 07:00 Uhr # → Prompt: "Venture Radar Research: 7 neue Geschäftsmodell-Kandidaten # DE/AT/CH, AI-Takeover-Potenzial, Matrix-Scoring. Update das Artifact." # → Läuft auf Anthropic Cloud, nicht auf deinem Mac
8

Explore → Plan → Implement für komplexe Methoden-Entwicklung

Bei Session-Design oder Interventions-Konzeption springst du oft direkt ins Tun. Plan Mode zuerst würde bedeuten: Claude liest Methoden-Bibliothek + Mandat-Akte, schlägt einen Plan vor, du genehmigst. Dann erst Umsetzung. Qualitativ besser, weil Claude den vollen Bibliotheks-Kontext hat bevor es gestaltet.

Prompt (in Cowork, Plan Mode aktiv per Shift+Tab)
# Plan Mode einschalten, dann: "Lies die Methoden-Bibliothek und die CHS Mandat-Akte. Ich will eine 3h Session für das CHS Leadership Team zu Priorisierung. Erstelle einen Interventions-Plan mit 3 Methoden-Optionen und begründe jede gegen Phase Fit + Mindset-Match." # → Plan reviewen → Normal Mode → Umsetzung
